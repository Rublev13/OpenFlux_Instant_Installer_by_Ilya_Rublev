## Быстрый запуск

Войдите на VPS по SSH под `root` или пользователем с правами `sudo`. Команда сама запросит административные права, если они нужны; может потребоваться пароль пользователя. Поддерживаются Ubuntu 22.04/24.04 и Debian 12/13, amd64/arm64, systemd. Для зарубежного выхода нужен зарубежный VPS.

Скопируйте команду целиком:

```bash
bash -c 'set -e; if [ "$EUID" -ne 0 ]; then exec sudo bash -c "$BASH_EXECUTION_STRING"; fi; if ! command -v curl >/dev/null; then apt-get update; apt-get install -y ca-certificates curl; fi; of_tmp=$(mktemp -d); trap "rm -rf -- \"$of_tmp\"" EXIT; curl --proto "=https" --proto-redir "=https" -fsSL --connect-timeout 15 --max-time 180 "https://raw.githubusercontent.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev/main/openflux-install.sh" -o "$of_tmp/openflux-install.sh"; bash "$of_tmp/openflux-install.sh" --install'
```

Установка начнётся сразу. Вставьте публичную ссылку на Яндекс.Документ с доступом на редактирование вида `https://disk.yandex.ru/i/ИДЕНТИФИКАТОР`. Затем выберите режим: **1 для Android/ПК, 2 для iPhone/TestFlight**. Скрипт установит зависимости и OpenFlux, настроит автозапуск и покажет ссылку подключения с QR-кодом. Если редактор не определится автоматически, появится выбор редактора. **Шифрование AES-256-GCM включено в обоих режимах, ключ уже внутри ссылки и QR.**

После установки меню управления доступно командой `openflux-setup` под root или `sudo openflux-setup` под обычным пользователем. Полный исходник: [openflux-install.sh](openflux-install.sh).

**iPhone:** обновите OpenFlux в [TestFlight](https://testflight.apple.com/join/BwnAcdus), выберите на VPS режим 2 и импортируйте QR. В обновлённой сборке исправлен перенос ключа. Затем включите системный VPN. [Подключение с iPhone](#подключение-с-iphone).

## Как появилась идея

Работа началась с инструкции по установке OpenFlux на VPS. Хотелось разобрать настройку так, чтобы человек мог последовательно выполнить команды и понимать, что происходит на его сервере. Установить бинарный файл оказалось только частью задачи. Нужно было выбрать режим выходной ноды, разобраться с редакторами Яндекса, создать общий ключ, настроить службу и подготовить клиент на другом устройстве.

Затем возникли вопросы, которые естественно появляются при первой установке. Через какой сервер в итоге выходит трафик? Нужно ли каждый раз вводить команды на компьютере? Можно ли подключиться с телефона? Как перенести ссылку на документ и ключ, ничего не перепутав? Как удалить всё, когда эксперимент закончен?

В этот момент стало понятно, что удобнее собрать настройку в один установщик. Человек указывает ссылку, а повторяющиеся действия выполняет скрипт. Он определяет архитектуру VPS, проверяет загруженный файл, создаёт необходимые каталоги и устанавливает службу. После перезагрузки сервера OpenFlux запускается автоматически.

Отдельное внимание пришлось уделить тому, что происходит после установки. Просто написать «готово» недостаточно: пользователю нужны параметры клиента, способ повторно показать QR-код и понятная команда удаления. Поэтому в меню есть управление установленным экземпляром, а рядом с конфигурацией сохраняется клиентский архив. Его можно забрать с VPS и использовать при настройке компьютера.

Я хотел сохранить прозрачность обычного Bash-скрипта. Исходный файл можно открыть и прочитать до запуска. В нём видны версия OpenFlux, адрес загрузки, создаваемая служба и пути удаления. Если на сервере уже есть другая установка в тех же местах, скрипт останавливается, чтобы не перезаписать её настройки.

Сам OpenFlux разработан участниками отдельного проекта. Этот репозиторий содержит установщик и документацию к выбранному способу развёртывания. Ссылки на исходное ядро и Android-клиент сохранены: по ним можно изучить протокол, посмотреть изменения и проверить ограничения конкретной версии.

## Что делает OpenFlux

[OpenFlux](https://github.com/p1neappleXpress/OpenFlux) реализует сетевой туннель с несколькими вариантами транспорта. В этой версии установщика используется транспорт через Яндекс.Документы. Клиент и сервер работают с одной ссылкой на документ и одним секретом подключения.

Приложение на устройстве передаёт трафик локальному клиенту OpenFlux. Клиент упаковывает его и отправляет через выбранный транспорт. OpenFlux на VPS принимает эти данные и устанавливает исходящие соединения с конечными ресурсами. Ответы возвращаются клиенту через тот же транспорт.

Сервисы совместного редактирования здесь используются как канал передачи данных между двумя экземплярами программы. Документ не выбирает страну выхода и не заменяет VPS. Внешний адрес, который увидят конечные ресурсы для таких соединений, относится к выходу вашего сервера, в том числе к его NAT, если он используется.

**Если нужен зарубежный выход, устанавливайте серверную часть на зарубежный VPS.** Установка этого скрипта на российский сервер сама по себе не создаёт зарубежный выход или каскад из двух серверов.

Для сервера выбран режим `l4`. Обработка туннеля выполняется в пользовательском пространстве, после чего ядро OpenFlux открывает обычные исходящие соединения. Установщик не добавляет правила firewall и не меняет маршруты сервера. Для выбранного транспорта ему не нужен отдельный входящий порт OpenFlux. Исходящий доступ к Яндексу и конечным ресурсам должен быть разрешён.

| Обновление без перенастройки | Пункт 6 сохраняет документ, ключ, cookies и выбранный режим |
| Резервная копия | Предыдущие файлы и cookies сохраняются в каталоге, доступном только root |
| Обработка ошибок | Проверка стабильности процесса 20 секунд; автоматический откат при ошибке; отдельное сообщение о серверной капче |
| Удаление | Пункт 2 удаляет экземпляр, созданный этим установщиком, после подтверждения |

Минимальные CPU и RAM экспериментально не установлены. Для первой проверки используйте отдельный VPS, на котором нет важных сервисов. Установщик рассчитан на одну активную клиентскую сессию.

Создайте отдельный пустой документ в Яндекс.Документах. Откройте «Поделиться», разрешите редактирование по ссылке и скопируйте полученный адрес. Проверьте его в окне инкогнито: документ должен открываться для редактирования без входа в ваш аккаунт.

Установщик принимает публичные ссылки такого вида:

```text
https://disk.yandex.ru/i/ИДЕНТИФИКАТОР
```

Домен `disk.yandex.ru` в ссылке на общий документ является нормальным. Ссылка на главную страницу Диска, папку, личный раздел или страницу, требующую входа, не подходит. Используйте документ без личной и рабочей информации.

| Новый редактор, Волга | `vyandex` | VOLGA / `volga` |

Редактор определяется по конфигурации страницы документа, а не по виду публичной ссылки: оба могут использовать `disk.yandex.ru/i/…`. Ручной выбор транспорта не меняет редактор самого документа. Если документ открывается в Волге, назначение ему `yandex` не превращает его в старый документ и может привести к ошибке авторизации.

Для обоих редакторов доступны режим Android/ПК с `batched` и Session и режим iPhone с `legacy` без Session. AES-256-GCM включено в каждом варианте. При смене документа повторите настройку и импортируйте новый профиль: существующий секрет сохраняется, а ссылка и контекст шифрования обновляются.

Конфигурации обоих редакторов проверяются отдельно. Полное соединение через реальные документы не подтверждено автоматическими тестами. Обновлённый TestFlight корректно импортирует ключ. Успешная капча в приложении не подтверждает авторизацию серверного IP; это проверяется отдельно.

## Установка одной командой

Войдите на VPS по SSH под `root` или пользователем с правами `sudo`. Команда сама запросит административные права через `sudo`, если они нужны.

Скопируйте всю строку:

```bash
bash -c 'set -e; if [ "$EUID" -ne 0 ]; then exec sudo bash -c "$BASH_EXECUTION_STRING"; fi; if ! command -v curl >/dev/null; then apt-get update; apt-get install -y ca-certificates curl; fi; of_tmp=$(mktemp -d); trap "rm -rf -- \"$of_tmp\"" EXIT; curl --proto "=https" --proto-redir "=https" -fsSL --connect-timeout 15 --max-time 180 "https://raw.githubusercontent.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev/main/openflux-install.sh" -o "$of_tmp/openflux-install.sh"; bash "$of_tmp/openflux-install.sh" --install'
```

Команда при необходимости установит `curl` и сертификаты, скачает скрипт во временный каталог и сразу запустит установку. Файл будет полностью загружен до начала исполнения. Временная копия удалится при завершении команды.

Дальше нужно:

1. Вставить публичную ссылку на документ.
2. Выбрать режим: **1 для Android/ПК** или **2 для iPhone/TestFlight**.
3. Дождаться определения редактора. Если оно не сработало, выбрать старый или новый редактор вручную либо отменить установку.
4. Дождаться запуска службы и появления параметров подключения.

Скрипт устанавливает **OpenFlux node-v1.0.1**. Серверный релиз и SHA-256 для amd64/arm64 закреплены в исходнике. В нём исправлено определение роли выхода после чтения конфигурации: от роли зависят стороны шифрования и Session. Явный `--role=exit` также сохранён в службе.

| Компонент | Закреплённая / проверяемая версия |
| --- | --- |
| Серверное ядро | [node-v1.0.1](https://github.com/p1neappleXpress/OpenFlux/releases/tag/node-v1.0.1) |
| Android, официальный клиент | [v2.0.1](https://github.com/p1neappleXpress/OpenFluxAndroid/releases/tag/v2.0.1) |
| Desktop, официальный клиент | [v2.0.2](https://github.com/p1neappleXpress/OpenFluxDesktop/releases/tag/v2.0.2) |
| Дополнительный CLI из клиентского архива | [v0.1.0](https://github.com/p1neappleXpress/OpenFlux/releases/tag/v0.1.0) |
| iPhone | Обновлённая сборка TestFlight; точный номер проверенной сборки не зафиксирован |

Версия CLI указана отдельно: серверный релиз `node-v1.0.1` не содержит Windows-бинарника. Исправления авторизации Волги, обмена cookies и окна защиты от повторов из v0.1.0 входят в выбранное серверное ядро. Они не отменяют требования Яндекса пройти капчу на IP VPS.

Если вы скачали файл заранее, запустите его из папки, в которой он находится:

```bash
bash openflux-install.sh
```

После установки меню доступно так:

```bash
openflux-setup
```

| Пункт | Действие |
| --- | --- |
| 1 | Установить или перенастроить OpenFlux |
| 2 | Полностью удалить принадлежащую установщику установку |
| 3 | Показать QR-код и ссылку подключения |
| 4 | Показать текущий ключ шифрования |
| 5 | Проверить ключ и профиль без вывода секрета |
| 6 | Обновить с сохранением ключа, документа, cookies и режима |
| 0 | Выйти |

Команды управления сервером ниже приведены для сессии `root`. Если работаете под обычным пользователем, добавляйте перед ними `sudo`.

## Обновление существующей установки

Запустите на VPS следующую команду целиком. Она скачает актуальный установщик и сразу выполнит обновление. Повторно вводить документ и выбирать режим не потребуется.

```bash
bash -c 'set -e; if [ "$EUID" -ne 0 ]; then exec sudo bash -c "$BASH_EXECUTION_STRING"; fi; if ! command -v curl >/dev/null; then apt-get update; apt-get install -y ca-certificates curl; fi; of_tmp=$(mktemp -d); trap "rm -rf -- \"$of_tmp\"" EXIT; curl --proto "=https" --proto-redir "=https" -fsSL --connect-timeout 15 --max-time 180 "https://raw.githubusercontent.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev/main/openflux-install.sh" -o "$of_tmp/openflux-install.sh"; bash "$of_tmp/openflux-install.sh" --update'
```

Сохраняются точная ссылка документа, ключ AES, cookies, режим `ios`/`session` и настройки `server.conf`. Профили и QR формируются заново с тем же секретом. При неизменных документе и режиме рабочий профиль телефона удалять не нужно.

Перед заменой файлов сохраняется резервная копия в `/var/backups/openflux-rublev/snapshot.…` с доступом только root. При ошибке установки или обнаруженном перезапуске процесс получает прежние бинарник, конфигурацию и cookies. Общие пакеты ОС откат не удаляет. Если прежняя установка уже не работала, возврат к ней сам по себе её не исправит.

Отказ запуска из-за серверной капчи обрабатывается отдельно: новая установка сохраняется, служба останавливается, выводится ссылка на [CAPTCHA.md](CAPTCHA.md), команда завершается кодом `2`. Это состояние требует ручной авторизации VPS. Оно не обозначается как готовое подключение. При успешной проверке код завершения — `0`; при ошибке — `1`.

Пункт 6 и `sudo openflux-setup --update` устанавливают версию, закреплённую в уже скачанном скрипте. Чтобы получить будущую версию установщика, используйте команду загрузки выше. Обновление не меняет редактор документа, режим клиента и приложение на телефоне. Для изменения документа или режима используйте пункт 1.

## Подключение с Android

1. Установите официальный [OpenFluxAndroid v2.0.1](https://github.com/p1neappleXpress/OpenFluxAndroid/releases/tag/v2.0.1). Если архитектура неизвестна, возьмите APK с `universal` в имени.
2. Для новой установки выберите на VPS режим **1, Android/ПК**. Если сервер уже настроен в режиме `ios`, импортируйте его профиль без ручного включения Session: новый Android-клиент поддерживает оба формата.
3. Откройте профили в приложении и импортируйте ссылку `openflux://v1/…` либо QR. Проверьте сохранённый секрет, документ и режим.
4. Выберите **системный VPN**, разрешите его Android и подключитесь. Локальный SOCKS сам по себе не переводит браузер в туннель.
5. Откройте сайт проверки IP и сравните адрес с выходным IP VPS.

| Клиент | Совместимость профиля |
| --- | --- |
| Официальный `p1neappleXpress/OpenFluxAndroid v2.0.1` | Штатный импорт ссылки/QR, секрета, кодека и Session |
| Альтернативный `damnurmum/OpenFlux-Android v1.1.1` | Поддерживает тот же формат; сохранена проверка декодера |
| Старый официальный `OpenFluxAndroid 0.0.2` | Другой формат QR и нет нужной настройки AES; обновите приложение |

Чтобы повторно показать ссылку и QR:

```bash
openflux-setup --qr
```

Если QR переносится на новую строку, расширьте терминал или скачайте по SFTP `/etc/openflux/connection.png`. PNG есть и в `/etc/openflux/client.zip`. Ссылка предназначена для совместимых клиентов OpenFlux.

**Ссылка, QR и архив содержат ключ подключения. Не публикуйте их.**

## Подключение с Windows и других компьютеров

Для подключения без командной строки используйте официальный [OpenFluxDesktop v2.0.2](https://github.com/p1neappleXpress/OpenFluxDesktop/releases/tag/v2.0.2).

1. Скачайте сборку для своей ОС. Для Windows 10/11 x64 доступны установщик и portable ZIP; для Linux — DEB/архив; для macOS — DMG своей архитектуры.
2. Импортируйте ссылку `openflux://v1/…`, которую выдаёт VPS, и выберите профиль.
3. В Windows включите **системный прокси** для браузера либо **полный туннель** для маршрутизации через Wintun. Полный туннель требует административных прав.
4. Подключитесь и проверьте внешний IP. На Linux/macOS эта версия предлагает локальные SOCKS5 `127.0.0.1:1080` и HTTP-прокси `127.0.0.1:1081`: их нужно указать в настройках нужного приложения.

Первое открытие встроенного браузера для капчи может потребовать отдельной загрузки. Возможности платформ различаются; подробности — в README клиентского проекта.

### Дополнительный вариант: CLI

Скачайте по SFTP `/etc/openflux/client.zip`, распакуйте его и следуйте `README.txt` внутри. Для Windows используется [CLI v0.1.0 x64](https://github.com/p1neappleXpress/OpenFlux/releases/download/v0.1.0/openflux-windows-amd64.exe). Переименуйте его в `openflux.exe`, положите рядом с `start-openflux.cmd` и запустите этот файл двойным щелчком. SHA-256 приведена в архиве.

Укажите в браузере SOCKS5 `127.0.0.1:1080`. В Firefox поля HTTP/HTTPS при этом остаются пустыми. Этот вариант обслуживает только настроенные приложения. Для остановки нажмите `Ctrl+C` в окне CLI и отключите прокси в браузере.

## Подключение с iPhone

Обновите OpenFlux в [TestFlight](https://testflight.apple.com/join/BwnAcdus). Корректный импорт ключа в обновлённой сборке подтверждён при пользовательской проверке; номер сборки не зафиксирован. Это подтверждение импорта, а не полного прохождения интернет-трафика.

1. При новой установке выберите на VPS **2, iPhone/TestFlight**. Для перенастройки существующего сервера: `sudo openflux-setup --install-ios`. Используются `legacy`, AES-256-GCM и отключённый Session.
2. Импортируйте QR или ссылку OpenFlux. Для нового редактора транспорт может называться **VOLGA / Волга**. Откройте профиль повторно и убедитесь, что **«Шифрование (AES-256-GCM) → Общий секрет»** заполнено. Новый ключ на телефоне создавать не нужно.
3. Включите **системный VPN** и разрешите добавление VPN-конфигурации в iOS. Локальный SOCKS `127.0.0.1:10808` внутри приложения не подключает Safari автоматически. Одновременно внутренний клиент и системный VPN не запускайте.
4. Если приложение показывает капчу, пройдите её. Затем откройте Safari, проверьте загрузку обычного сайта и внешний IP — он должен соответствовать VPS.

При подключении `encryption: secret set (64 chars)` подтверждает наличие секрета в клиенте. `encryption: off` означает, что шифрование клиента выключено. Непустое поле само по себе ещё не доказывает совпадение ключа с сервером.

Если ключ после импорта пуст, сначала обновите TestFlight и импортируйте профиль повторно. [Описание старой ошибки и ручного переноса](patches/README.md) сохранено для прежних сборок; применять патч к работающему обновлённому приложению не требуется.

Session на iOS этим обновлением установщика не включается: исправление импорта ключа не подтверждает поддержку согласования сессии. При серверной ошибке `captcha required` используйте [инструкцию для IP VPS](CAPTCHA.md). Капча на телефоне и капча выходного сервера могут потребовать отдельных действий.

## Ключ шифрования

Шифрование включено и для Android/ПК, и для iPhone. При первой установке `openssl rand -hex 32` создаёт отдельный секрет. Он сохраняется в `/etc/openflux/secret.txt` и используется сервером, клиентским архивом, ссылкой и QR. Общего встроенного ключа для всех установок нет.

Показать свой ключ:

```bash
sudo openflux-setup --key
```

При перенастройке скрипт сохраняет существующий ключ. Если он отсутствует, повреждён или заменён символьной ссылкой, операция останавливается без подмены секрета. Отсутствующий или пустой файл ключа не позволяет ядру запуститься с указанным параметром шифрования. Права на файл ключа: `0640`, доступ у root и группы службы; экспортированные профили доступны только root (`0600`).

Не публикуйте вывод команды, QR или ссылку подключения. Изменение режима `negotiate` не отключает шифрование.

Проверка файлов на VPS без вывода ключа и ссылки:

```bash
sudo openflux-setup --check
```

Команда сверяет ключ в ссылке с файлом VPS, документ, контекст шифрования, транспорт, кодек и параметры запуска в файле службы. Она не проверяет содержимое профиля на телефоне, активные переопределения systemd или прохождение трафика. Если параметры отличаются, повторите быстрый запуск свежего установщика и импортируйте новый профиль.

## Как проверить соединение

Сначала подключите клиент. На компьютере откройте в браузере с настроенным SOCKS5 адрес [api.ipify.org](https://api.ipify.org). Ожидается внешний IPv4-адрес выхода VPS.

На Windows также можно проверить соединение из командной строки:

```bat
curl.exe -4 --proxy socks5://127.0.0.1:1080 --connect-timeout 20 --max-time 40 https://api.ipify.org
```

Состояние `active` у службы подтверждает, что процесс запущен. Оно не подтверждает доступность документа, отсутствие капчи, успешное согласование с клиентом или прохождение запросов до конечного ресурса.

### Подключено и пингуется, но сайты не открываются

В проверенной iOS-ветке кнопка «Пинг» делает HTTP HEAD к корню сайта документа. Она не проверяет связь с выходной нодой, секрет или передачу интернет-трафика ([исходник PingService](https://github.com/saharev1/OpenFlux/blob/17557e472b7f11b66f1cfeba8283dc6f69b234c0/ios-app/OpenFlux/PingService.swift)). Для проверки выхода используйте «Доступность» при включённом системном VPN и сверяйте полученный IP с VPS. В Android также зарегистрирован случай ложного статуса «Подключено» при нулевом трафике на выходной ноде ([issue #9](https://github.com/p1neappleXpress/OpenFluxAndroid/issues/9)).

- Проверяйте устройства по одному. Одна установка не рассчитана на одновременное обслуживание нескольких клиентов.
- На обоих концах должны совпадать документ, секрет, кодек и Session. `ios` означает `legacy` без Session; `session` — `batched` с Session. В официальном Android v2.0.1 и альтернативном v1.1.1 импорт кода режима `ios` также сохраняет `legacy` и отключённый Session; при ручной настройке эти параметры нужно выставить самостоятельно.
- Если документ открывается и WebSocket подключён, но журнал клиента показывает `[BRIDGE] encryption: off`, проверьте сохранённый общий секрет в профиле: при включённом AES на VPS такой клиент не сможет передавать полезный трафик. Подключение к документу предшествует проверке обмена с выходом; это относится и к старому редактору.
- Капча клиента и капча VPS — разные проверки. Успешная проверка на телефоне не подтверждает авторизацию сервера; передача cookies требует поддерживаемого рабочего канала.
- Если на VPS повторяется `captcha required` и растёт `NRestarts`, используйте [ручное прохождение капчи через IP VPS и импорт cookies](CAPTCHA.md). Для этого добавлена отдельная утилита; переустановка и смена ключа не требуются.
- В официальных обсуждениях есть проблемы старого редактора с WebSocket/Engine.IO и авторизацией на VPS ([#31](https://github.com/p1neappleXpress/OpenFlux/issues/31), [#106](https://github.com/p1neappleXpress/OpenFlux/issues/106)). Это возможные причины, которые нужно сверять с журналом сервера. Сама строка `WebSocket connected` не доказывает обмен с другим участником документа.

Для отчёта без секретов выполните на VPS:

```bash
bash -c 'set -e; of_diag=$(mktemp); trap "rm -f -- \"$of_diag\"" EXIT; curl --proto "=https" --proto-redir "=https" -fsSL --connect-timeout 15 --max-time 60 https://raw.githubusercontent.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev/main/openflux-diagnose.py -o "$of_diag"; if [ "$EUID" -eq 0 ]; then python3 "$of_diag"; else sudo python3 "$of_diag"; fi'
```

[Диагностика](openflux-diagnose.py) только читает файлы и сведения systemd: ничего не устанавливает, не меняет и не перезапускает. Она наблюдает службу 20 секунд, обнаруживает смену процесса и рост перезапусков, показывает режим, соответствие ключа и ссылки, параметры процесса, хэш node-v1.0.1 и счётчики ошибок. Штатный `--role=exit` не помечается как постороннее переопределение. Исходные строки журнала, ключи, документы, QR и cookies в отчёт не попадают. Отчёт можно приложить к вопросу вместе с названием и номером сборки клиента. Это не проверка полного соединения; отсутствие ошибок в отчёте не гарантирует исправность, особенно при отключённых подробных логах.

| Настроить режим iPhone без negotiate | `openflux-setup --install-ios` |
| Удалить установку | `openflux-setup --uninstall` |

При повторной настройке сохраняется существующий ключ. Если вы изменили документ, транспорт или режим клиента, заново импортируйте профиль: старая ссылка подключения не обновится сама. Каждый экземпляр сервера работает в одном выбранном режиме.

## Что создаётся на VPS

| Путь | Содержимое |
| --- | --- |
| `/usr/local/bin/openflux` | Бинарный файл OpenFlux |
| `/usr/local/sbin/openflux-setup` | Меню управления установкой |
| `/etc/systemd/system/openflux.service` | Служба автозапуска |
| `/var/backups/openflux-rublev/` | Резервные копии перед обновлением/перенастройкой, только root |
| `/etc/openflux/` | Конфигурация, ключ, ссылка, QR и клиентский архив |
| `/var/lib/openflux/` | Рабочие данные и cookies транспорта |
| `/var/log/openflux/` | Журналы OpenFlux |
| `/etc/logrotate.d/openflux` | Настройка ротации журналов |

В зависимости от состояния ОС могут устанавливаться `ca-certificates`, `curl`, `openssl`, `python3`, `logrotate` и `qrencode`. Сам процесс OpenFlux работает от отдельного пользователя `openflux-rublev`.

## Полное удаление установки

Откройте меню и выберите пункт 2 либо выполните:

```bash
openflux-setup --uninstall
```

Скрипт покажет пути удаления и попросит ввести `УДАЛИТЬ`. Будут остановлена и отключена служба, удалены файлы OpenFlux, параметры подключения, ключ, QR, архив, рабочие данные, резервные копии в `/var/backups/openflux-rublev/`, собственные журналы и созданная учётная запись.

Под полным удалением здесь понимается удаление экземпляра, созданного этим установщиком. Он не ищет и не уничтожает другие установки OpenFlux по всему серверу. Обнаруженная чужая установка в используемых путях требует отдельной проверки.

Общие пакеты ОС, записи системного journal, ваша отдельно скачанная копия скрипта и служебный файл блокировки в `/run/lock/` не удаляются. Они не являются рабочим экземпляром OpenFlux. Копии ключей и профилей на телефонах, компьютерах и в самостоятельно созданных резервных копиях также нужно удалить отдельно. Скрипт не удаляет документ из аккаунта Яндекса и не меняет его настройки общего доступа.

## Известные ограничения

Эта сборка рассчитана на одну активную клиентскую сессию. Несколько независимых пользователей, отдельные ключи для каждого, квоты, подписки и панель управления в неё не входят.

Зависимость от стороннего транспорта остаётся. Капча, требование входа, закрытые права на документ, изменение протокола Яндекса или сетевые ограничения могут помешать соединению при работающей службе. Автоматическое определение редактора тоже может не сработать.

Режим работы клиента имеет значение. SOCKS5 на компьютере не переводит весь трафик системы в туннель. В закреплённой версии ядра разрешение DNS-имён может оставаться локальным. Работа IPv6 и всех возможных UDP-сценариев этим установщиком не подтверждена.

Если на сервере используется другая версия Ubuntu, Debian, другая архитектура или отсутствует `systemd`, установщик остановится. Версия OpenFlux не обновляется сама вслед за релизами исходного проекта.

## Что проверено

Автоматические проверки запускаются в [GitHub Actions](https://github.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev/actions/workflows/check.yml). Они используют только синтетические документы и временные случайные ключи.

- Синтаксис Bash/Python, генерация профилей, одинаковые ключ, документ, контекст, кодек и Session в сервере, ссылке и архиве.
- Установка, обновление, сохранение существующего ключа и cookies, резервная копия, откат после перезапуска, неверный SHA-256, капча при старте, удаление и защита чужой установки. Системные операции в этих сценариях заменены имитацией.
- Отдельные задания для `yandex` и `vyandex`: определение редактора, ручной выбор, смена документа и оба режима. Страницы документов синтетические.
- Настоящие PNG через `qrencode` и `zbarimg`; исполнение неизменённого Kotlin-декодера и `Profile.fromShare` из общего модуля Android v2.0.1 / Desktop v2.0.2. Проверяется также точность контекста со слешем в конце ссылки. Сохранена проверка Go-декодера альтернативного Android v1.1.1.
- SHA-256 релизных Linux-бинарников и реальный зашифрованный обмен HTTP между клиентом и выходом в CI. Проверяются явный `--role=exit` и исправленный `Role = exit` из INI. Для этого теста используется Direct на loopback; установщик Direct не включает.
- Историческая проверка Swift-импорта и патча старой iOS-ветки. Она не проверяет текущую подписанную TestFlight-сборку, Keychain или VPN-расширение.
- Диагностика без ключей, ссылок и cookies, а также безопасный импорт cookies для обоих редакторов.

Эти проверки не заменяют запуск на реальном VPS и телефоне через действующий документ Яндекса. Проверка реального выхода — загрузка сайта и совпадение внешнего IP с VPS при включённом системном VPN. Статус приложения «подключено», пинг документа и `systemd active` по отдельности этого не доказывают.
