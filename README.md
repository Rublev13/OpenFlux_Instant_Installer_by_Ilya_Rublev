# OpenFlux_Instant_Installer by_Ilya_Rublev

Установщик OpenFlux для собственного Linux VPS. Одна команда открывает меню, после чего остаётся выбрать установку и вставить публичную ссылку на отдельный документ Яндекса. Скрипт скачает закреплённую версию OpenFlux, создаст ключ, подготовит службу автозапуска и выдаст настройки подключения.

## Как появилась идея

Работа началась с инструкции по установке OpenFlux на VPS. Хотелось разобрать настройку так, чтобы человек мог последовательно выполнить команды и понимать, что происходит на его сервере. Установить бинарный файл оказалось только частью задачи. Нужно было выбрать режим выходной ноды, разобраться с редакторами Яндекса, создать общий ключ, настроить службу и подготовить клиент на другом устройстве.

Затем возникли вопросы, которые естественно появляются при первой установке. Через какой сервер в итоге выходит трафик? Нужно ли каждый раз вводить команды на компьютере? Можно ли подключиться с телефона? Как перенести ссылку на документ и ключ, ничего не перепутав? Как удалить всё, когда эксперимент закончен?

В этот момент стало понятно, что удобнее собрать настройку в один установщик. Человек указывает ссылку, а повторяющиеся действия выполняет скрипт. Он определяет архитектуру VPS, проверяет загруженный файл, создаёт необходимые каталоги и устанавливает службу. После перезагрузки сервера OpenFlux запускается автоматически.

Отдельное внимание пришлось уделить тому, что происходит после установки. Просто написать «готово» недостаточно: пользователю нужны параметры клиента, способ повторно показать QR-код и понятная команда удаления. Поэтому в меню есть управление установленным экземпляром, а рядом с конфигурацией сохраняется клиентский архив. Его можно забрать с VPS и использовать при настройке компьютера.

Я хотел сохранить прозрачность обычного Bash-скрипта. Исходный файл можно открыть и прочитать до запуска. В нём видны версия OpenFlux, адрес загрузки, создаваемая служба и пути удаления. Если на сервере уже есть другая установка в тех же местах, скрипт останавливается, чтобы не перезаписать её настройки.

Сам OpenFlux разработан участниками отдельного проекта. Этот репозиторий содержит установщик и документацию к выбранному способу развёртывания. Ссылки на исходное ядро и Android-клиент сохранены: по ним можно изучить протокол, посмотреть изменения и проверить ограничения конкретной версии.

## Что делает OpenFlux

[OpenFlux](https://github.com/p1neappleXpress/OpenFlux) реализует сетевой туннель с несколькими вариантами транспорта. В этой версии установщика используется транспорт через Яндекс.Документы. Клиент и сервер работают с одной ссылкой на документ и одним секретом подключения.

Приложение на устройстве передаёт трафик локальному клиенту OpenFlux. Клиент упаковывает его и отправляет через выбранный транспорт. OpenFlux на VPS принимает эти данные и устанавливает исходящие соединения с конечными ресурсами. Ответы возвращаются клиенту через тот же транспорт.

Сервисы совместного редактирования здесь используются как канал передачи данных между двумя экземплярами программы. Документ не выбирает страну выхода и не заменяет VPS. Внешний адрес, который увидят конечные ресурсы для таких соединений, относится к выходу вашего сервера, в том числе к его NAT, если он используется.

**Если нужен зарубежный выход, устанавливайте серверную часть на зарубежный VPS.** Установка этого скрипта на российский сервер сама по себе не создаёт зарубежный выход или каскад из двух серверов.

Для сервера выбран режим `l4`. Обработка туннеля выполняется в пользовательском пространстве, после чего ядро OpenFlux открывает обычные исходящие соединения. Установщик не добавляет правила firewall и не меняет маршруты сервера. Для выбранного транспорта ему не нужен отдельный входящий порт OpenFlux. Исходящий доступ к Яндексу и конечным ресурсам должен быть разрешён.

Минимальные CPU и RAM экспериментально не установлены. Для первой проверки используйте отдельный VPS, на котором нет важных сервисов. Установщик рассчитан на одну активную клиентскую сессию.

Создайте отдельный пустой документ в Яндекс.Документах. Откройте «Поделиться», разрешите редактирование по ссылке и скопируйте полученный адрес. Проверьте его в окне инкогнито: документ должен открываться для редактирования без входа в ваш аккаунт.

Установщик принимает публичные ссылки такого вида:

```text
https://disk.yandex.ru/i/ИДЕНТИФИКАТОР
```

Домен `disk.yandex.ru` в ссылке на общий документ является нормальным. Ссылка на главную страницу Диска, папку, личный раздел или страницу, требующую входа, не подходит. Используйте документ без личной и рабочей информации.

## Установка одной командой

**Закрытое тестирование:** пока репозиторий приватный, команда ниже без авторизации не скачает файл. Откройте [openflux-install.sh](openflux-install.sh) в GitHub под своим аккаунтом, скачайте файл через кнопку **Download raw file** и перенесите его на VPS по SFTP. В каталоге с файлом выполните `sudo bash openflux-install.sh`. Подробный порядок и проверка соединения: [TESTING.md](TESTING.md).

**После открытия репозитория:** используйте следующую команду без подстановок.

Войдите на VPS по SSH под `root`. Если работаете под обычным пользователем с административными правами, сначала выполните `sudo -i`.

Скопируйте всю строку:

```bash
bash -c 'set -e; test "$EUID" -eq 0 || { echo "Сначала выполните sudo -i"; exit 1; }; if ! command -v curl >/dev/null; then apt-get update; apt-get install -y ca-certificates curl; fi; of_tmp=$(mktemp -d); trap "rm -rf -- \"$of_tmp\"" EXIT; curl --proto "=https" --proto-redir "=https" -fsSL --connect-timeout 15 --max-time 180 "https://raw.githubusercontent.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev/main/openflux-install.sh" -o "$of_tmp/openflux-install.sh"; bash "$of_tmp/openflux-install.sh"'
```

Команда при необходимости установит `curl` и сертификаты, скачает скрипт во временный каталог и откроет его меню. Файл будет полностью загружен до начала исполнения. Временная копия удалится при завершении команды.

Дальше нужно:

1. Выбрать **1. Установить / перенастроить OpenFlux**.
2. Вставить публичную ссылку на документ.
3. Дождаться определения редактора. Если оно не сработало, выбрать старый или новый редактор вручную либо отменить установку.
4. Дождаться запуска службы и появления параметров подключения.

Скрипт устанавливает **OpenFlux 0.0.5**. Версия закреплена вместе с контрольными суммами. Автоматического перехода на любой новый релиз здесь нет.

Если вы скачали файл заранее, запустите его из папки, в которой он находится:

```bash
bash openflux-install.sh
```

После установки меню доступно так:

```bash
openflux-setup
```

| Пункт | Действие |
| --- | --- |
| 1 | Установить или перенастроить OpenFlux |
| 2 | Полностью удалить принадлежащую установщику установку |
| 3 | Показать QR-код и ссылку подключения |
| 0 | Выйти |

Все команды управления сервером в этой инструкции приведены для сессии `root`.

## Подключение с Android

Используйте [OpenFlux-Android v1.1.1 от damnurmum](https://github.com/damnurmum/OpenFlux-Android/releases/tag/v1.1.1). Формат ссылки и настройки сессии сверены с исходным кодом этого клиента. Полное соединение именно этой сборки с установленным VPS ещё требует практической проверки.

Откройте в приложении раздел «Профили», нажмите кнопку QR и отсканируйте код с экрана терминала. Проверьте импортированный профиль, сохраните его и подключитесь. При выборе VPN-режима подтвердите системный запрос Android.

Ссылка подключения имеет вид `openflux://v1/…`. В неё упакованы ссылка на документ, транспорт, секрет и параметры сессии. Её можно открыть на устройстве с приложением, которое умеет обрабатывать такой формат. Это формат OpenFlux; импорт в произвольный VPN-клиент не предполагается.

Чтобы показать ссылку и QR повторно:

```bash
openflux-setup --qr
```

Если терминал переносит QR на новую строку, расширьте окно. Можно также скачать по SFTP файл `/etc/openflux/connection.png` и открыть картинку. Тот же PNG включён в клиентский архив.

**Ссылка и QR содержат ключ подключения. Не публикуйте их.**

## Подключение с Windows

Скачайте с VPS через SFTP файл `/etc/openflux/client.zip` и распакуйте его в отдельную папку на компьютере. Внутри есть `README.txt`, конфигурация и ключ.

Загрузите [официальный бинарный файл OpenFlux 0.0.5 для Windows x64](https://github.com/p1neappleXpress/OpenFlux/releases/download/0.0.5/openflux-windows-amd64.exe), переименуйте его в `openflux.exe` и поместите рядом с `start-openflux.cmd`. Проверочная SHA-256 указана в `README.txt` внутри архива.

Запустите `start-openflux.cmd` двойным щелчком и оставьте окно открытым. Для последующих запусков вводить команду в PowerShell не понадобится.

Укажите в браузере или другом приложении SOCKS5-прокси `127.0.0.1`, порт `1080`. В Firefox эти поля находятся в ручных настройках сети. Выберите SOCKS v5, поля HTTP и HTTPS оставьте пустыми.

Такое подключение обслуживает настроенные приложения. Автоматическая маршрутизация всего Windows-компьютера здесь не настраивается. Для остановки нажмите `Ctrl+C` в окне клиента и отключите прокси в браузере.

## Что с iPhone

В опубликованном коде iOS-клиента исходного проекта не найден импорт `openflux://` и не предусмотрен необходимый для этой конфигурации режим согласования сессии. Совместимость доступных сборок TestFlight с данным профилем не подтверждена.

Поэтому установщик не заявляет подключение iPhone по этому QR-коду. Для него потребуется клиентская сборка, поддерживающая формат профиля, шифрование и режим сессии данной конфигурации. Серверный скрипт не может добавить отсутствующий импорт в приложение на телефоне.

## Как проверить соединение

Сначала подключите клиент. На компьютере откройте в браузере с настроенным SOCKS5 адрес [api.ipify.org](https://api.ipify.org). Ожидается внешний IPv4-адрес выхода VPS.

На Windows также можно проверить соединение из командной строки:

```bat
curl.exe -4 --proxy socks5://127.0.0.1:1080 --connect-timeout 20 --max-time 40 https://api.ipify.org
```

Состояние `active` у службы подтверждает, что процесс запущен. Оно не подтверждает доступность документа, отсутствие капчи, успешное согласование с клиентом или прохождение запросов до конечного ресурса.

## Управление сервером

| Задача | Команда |
| --- | --- |
| Открыть меню | `openflux-setup` |
| Показать состояние службы | `openflux-setup --status` |
| Показать последние записи журнала | `openflux-setup --logs` |
| Показать параметры клиента, включая ключ | `openflux-setup --client` |
| Показать ссылку и QR | `openflux-setup --qr` |
| Перезапустить службу | `systemctl restart openflux` |
| Остановить службу | `systemctl stop openflux` |
| Запустить службу | `systemctl start openflux` |
| Изменить ссылку на документ | `openflux-setup --install` |
| Удалить установку | `openflux-setup --uninstall` |

При повторной настройке сохраняется существующий ключ. Если вы изменили документ или транспорт, заново импортируйте профиль на клиенте: старая ссылка подключения не обновится сама.

## Что создаётся на VPS

| Путь | Содержимое |
| --- | --- |
| `/usr/local/bin/openflux` | Бинарный файл OpenFlux |
| `/usr/local/sbin/openflux-setup` | Меню управления установкой |
| `/etc/systemd/system/openflux.service` | Служба автозапуска |
| `/etc/openflux/` | Конфигурация, ключ, ссылка, QR и клиентский архив |
| `/var/lib/openflux/` | Рабочие данные и cookies транспорта |
| `/var/log/openflux/` | Журналы OpenFlux |
| `/etc/logrotate.d/openflux` | Настройка ротации журналов |

В зависимости от состояния ОС могут устанавливаться `ca-certificates`, `curl`, `openssl`, `python3`, `logrotate` и `qrencode`. Сам процесс OpenFlux работает от отдельного пользователя `openflux-rublev`.

## Полное удаление установки

Откройте меню и выберите пункт 2 либо выполните:

```bash
openflux-setup --uninstall
```

Скрипт покажет пути удаления и попросит ввести `УДАЛИТЬ`. Будут остановлена и отключена служба, удалены файлы OpenFlux, параметры подключения, ключ, QR, архив, рабочие данные, собственные журналы и созданная учётная запись.

Под полным удалением здесь понимается удаление экземпляра, созданного этим установщиком. Он не ищет и не уничтожает другие установки OpenFlux по всему серверу. Обнаруженная чужая установка в используемых путях требует отдельной проверки.

Общие пакеты ОС, записи системного journal, ваша отдельно скачанная копия скрипта и служебный файл блокировки в `/run/lock/` не удаляются. Они не являются рабочим экземпляром OpenFlux. Копии ключей и профилей на телефонах, компьютерах и в резервных копиях также нужно удалить отдельно. Скрипт не удаляет документ из аккаунта Яндекса и не меняет его настройки общего доступа.

## Известные ограничения

Эта сборка рассчитана на одну активную клиентскую сессию. Несколько независимых пользователей, отдельные ключи для каждого, квоты, подписки и панель управления в неё не входят.

Зависимость от стороннего транспорта остаётся. Капча, требование входа, закрытые права на документ, изменение протокола Яндекса или сетевые ограничения могут помешать соединению при работающей службе. Автоматическое определение редактора тоже может не сработать.

Режим работы клиента имеет значение. SOCKS5 на компьютере не переводит весь трафик системы в туннель. В закреплённой версии ядра разрешение DNS-имён может оставаться локальным. Работа IPv6 и всех возможных UDP-сценариев этим установщиком не подтверждена.

Если на сервере используется другая версия Ubuntu, Debian, другая архитектура или отсутствует `systemd`, установщик остановится. Версия OpenFlux не обновляется сама вслед за релизами исходного проекта.

## Что проверено

На 27 сентября 2026 года выполнены проверка синтаксиса Bash, проверка файла службы через `systemd-analyze verify` и 14 сценариев с имитацией системных команд. Проверялись установка, перенастройка, сохранение ключа, отказ при неверной контрольной сумме, откат после ошибки запуска, отмена удаления, удаление принадлежащих скрипту файлов, защита чужой установки и выбор редактора.

GitHub Actions при каждом push и pull request проверяет синтаксис Bash, встроенные фрагменты Python и запуск `--help`. Установка OpenFlux в этой проверке не выполняется.

Эти проверки не были установкой на реальный VPS. Работа системных пакетов, полноценное подключение через действующий документ Яндекса и сканирование QR физическим телефоном в них не проверялись. Перед объявлением стабильного релиза нужен отдельный сквозной тест с реальным клиентом.

## Что можно добавить дальше

Планы для следующих версий: обновление закреплённого релиза с возможностью возврата, смена ключа с перевыпуском QR, несколько независимых экземпляров, диагностика соединения с клиента и экспорт обезличенного отчёта об ошибке. Подключение iOS можно будет заявить после появления и проверки совместимого клиента.

## Быстрый запуск

Перед первой установкой прочитайте отказ от ответственности в начале страницы. Команда ниже работает без авторизации после открытия репозитория. Для закрытого тестирования скачайте файл из GitHub и выполните шаги из [TESTING.md](TESTING.md).

```bash
bash -c 'set -e; test "$EUID" -eq 0 || { echo "Сначала выполните sudo -i"; exit 1; }; if ! command -v curl >/dev/null; then apt-get update; apt-get install -y ca-certificates curl; fi; of_tmp=$(mktemp -d); trap "rm -rf -- \"$of_tmp\"" EXIT; curl --proto "=https" --proto-redir "=https" -fsSL --connect-timeout 15 --max-time 180 "https://raw.githubusercontent.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev/main/openflux-install.sh" -o "$of_tmp/openflux-install.sh"; bash "$of_tmp/openflux-install.sh"'
```

После установки: `openflux-setup`. Полный исходник установщика: [openflux-install.sh](openflux-install.sh).
