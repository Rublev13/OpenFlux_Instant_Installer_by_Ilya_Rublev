## Текущее состояние

Репозиторий: [Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev](https://github.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev). Основная ветка: `main`. На этапе подготовки репозиторий приватный; открытие для всех выполняется отдельным решением владельца после проверки.

Владелец выбрал GNU GPL версии 3 при создании репозитория. Исходный файл `LICENSE` сохранён. Адрес репозитория уже подставлен в обе команды запуска README.

Следующий шаг: пройти [TESTING.md](TESTING.md) на отдельном VPS и записать результаты. Пароль от GitHub, персональный токен, SSH-ключ и рабочий секрет OpenFlux не нужны для публикации исходного кода и не должны попадать в репозиторий.

При необходимости выберите отдельный приватный контакт для сообщений об уязвимостях и обновите `SECURITY.md`. Публичный Telegram-канал не считается таким контактом автоматически.

## Что сделать перед публичным запуском

1. Проверить текст истории и позицию автора в дисклеймере. При необходимости передать правовую часть на проверку юристу применительно к месту и способу публикации.
2. Выполнить [TESTING.md](TESTING.md): установка, подключение Android, внешний IP, перезагрузка, повторная настройка и удаление.
3. Записать точные версии ОС и клиента, транспорт, commit установщика и фактический результат. До успешного сквозного теста сохранить оговорку о предварительной версии.
4. Проверить историю Git и журналы GitHub Actions на наличие секретов. `.gitignore` не удаляет данные, уже попавшие в commit. Клиентские профили, cookies и реальные ссылки на документы не должны становиться публичными.
5. Проверить авторство компонентов, файл `LICENSE` и адреса загрузки. Сохранить оговорку о неподтверждённой совместимости iPhone.
6. Когда владелец решит открыть проект, изменить видимость в GitHub: Settings → General → Danger Zone → Change repository visibility → Public. История репозитория и журналы Actions также станут доступны; проверьте их до смены видимости.
7. После открытия проверить оба блока команды запуска README из сессии без авторизации. Публичная команда не должна требовать подстановки логина или токена.
8. При желании выпустить предварительную версию `v1.0.0-rc.1`. Указать проведённые проверки и оставшиеся ограничения.

## Проверка файлов без установки

Из корня репозитория:

```bash
bash -n openflux-install.sh
python3 tests/check_embedded_python.py
bash openflux-install.sh --help
```

Эти команды проверяют синтаксис Bash и встроенного Python, затем выводят справку. Те же проверки описаны в GitHub Actions и запускаются при push и pull request. Они не доказывают работу туннеля. Полная проверка требует отдельного тестового сервера и клиента.
