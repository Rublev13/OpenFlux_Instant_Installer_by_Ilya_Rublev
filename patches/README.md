# Исправление импорта ключа в iOS

Автор патча: **Илья Рублев**. [Telegram](https://t.me/Rublev_YouTube) · [Boosty](https://boosty.to/rublev13) · [YouTube](https://www.youtube.com/@Ilya_Rublev).

Исходное приложение: [saharev1/OpenFlux, ios-testflight](https://github.com/saharev1/OpenFlux/tree/17557e472b7f11b66f1cfeba8283dc6f69b234c0), на базе [OpenFlux](https://github.com/p1neappleXpress/OpenFlux). Авторство установщика и патча не распространяется на исходное приложение. Условия GPL исходного проекта сохраняются.

В `ios-app/OpenFlux/ContentView.swift`, методе `ProfileEditorView.applyShareConfig`, импорт одного документного профиля записывает `cfg.secret` в `directKey`, даже когда у профиля нет прямого канала. При сохранении `encryptionKey` остаётся пустым и основное шифрование оказывается выключено. Импорт нескольких профилей использует другой путь, `ShareImporter.build`, где выбор поля уже учитывает наличие прямого канала.

Файл [ios-single-profile-encryption.patch](ios-single-profile-encryption.patch) приводит одиночный импорт к тому же правилу:

| Профиль | Поле общего секрета | Поле прямого канала |
| --- | --- | --- |
| Только документ | Секрет ссылки | Пусто |
| Только direct | Секрет ссылки | Пусто |
| Документ и direct | Пусто, согласно модели этого iOS-клиента | Секрет ссылки |
| Ссылка без секрета | Пусто | Пусто |

При импорте очищаются старые значения полей ключей и адреса прямого канала. Патч рассчитан на коммит `17557e472b7f11b66f1cfeba8283dc6f69b234c0`; на другой версии сначала проверьте различия. В копии исходников этой версии разработчик может выполнить `git apply --check /путь/ios-single-profile-encryption.patch`, затем применить патч через `git apply`.

Проверка `python3 tests/check_ios_import.py` запускается из репозитория установщика на macOS с установленным Swift. Она скачивает три закреплённых публичных исходника, проверяет SHA-256, применяет патч во временном каталоге и компилирует исходный и исправленный методы. Профили создаются самим установщиком с временными случайными ключами. Исходный метод должен воспроизвести неправильное поле; исправленный проверяется в семи сценариях.

Этот тест не собирает полное приложение, не проверяет доступ к Keychain и не запускает сетевой туннель. Для доставки исправления через TestFlight нужна подписанная сборка от разработчика приложения. Серверный установщик патч на телефон не применяет. Ошибку SmartCaptcha этот патч не исправляет.
