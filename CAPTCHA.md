# Капча на VPS: ручное восстановление авторизации

Автор утилиты: **Илья Рублев**.

[Telegram](https://t.me/Rublev_YouTube) · [YouTube](https://www.youtube.com/@Ilya_Rublev) · [Boosty](https://boosty.to/rublev13)

Этот способ нужен, если **в свежем журнале VPS** есть `Failed to start transport: auth: yandex docs: captcha required`, а `NRestarts` растёт. Успешная капча на телефоне не подтверждает авторизацию VPS. Кратковременное `active/running` между перезапусками тоже не означает, что выход работает.

OpenFlux v0.1.0 (как и 0.0.5) умеет читать cookies из файла перед авторизацией. Утилита [openflux-import-cookies.py](openflux-import-cookies.py) записывает туда cookies, полученные после ручной проверки в браузере через IP VPS. Она не решает капчу, не устанавливает браузер на сервер и не меняет ключ шифрования. Поддерживаются оба транспорта установщика: `yandex` и `vyandex`.

## 1. Остановите повторные запросы на VPS

В SSH-консоли сервера от `root`:

```bash
systemctl stop openflux.service
```

Посмотрите внешний IPv4 сервера; затем сравните его с адресом в браузере:

```bash
curl -4 --fail --silent --show-error --connect-timeout 10 --max-time 20 https://api.ipify.org
```

## 2. Откройте SSH-прокси на Windows

Откройте **отдельное окно PowerShell на компьютере**. Замените `IP_VPS` адресом своего сервера:

```powershell
ssh -N -D 127.0.0.1:1081 -o ExitOnForwardFailure=yes root@IP_VPS
```

Используйте тот же SSH-ключ, пароль и порт, с которыми обычно подключаетесь к серверу. Для другого порта добавьте, например, `-p 2222` перед `root@IP_VPS`. После входа окно без вывода — нормальное состояние. Оставьте его открытым. Если SSH сообщает об ошибке соединения или перенаправления порта, сначала устраните её.

## 3. Запустите отдельное окно Edge через VPS

В **ещё одном локальном окне PowerShell** выполните:

```powershell
$ofBrowserProfile = Join-Path $env:TEMP ("OpenFlux-Captcha-" + [guid]::NewGuid().ToString("N"))
$ofBrowserArgs = @(
    ('--user-data-dir="{0}"' -f $ofBrowserProfile)
    '--inprivate'
    '--no-first-run'
    '--proxy-server=socks5://127.0.0.1:1081'
    'https://api.ipify.org'
)
Start-Process msedge.exe -ArgumentList $ofBrowserArgs
```

Откроется отдельный профиль Microsoft Edge с временным прокси. На странице должен быть **тот же внешний IPv4**, который показал VPS. Если адрес другой или страница не открывается, дальше не продолжайте: браузер пока не использует нужный выход.

В этом окне откройте **тот самый публичный документ, который указан в конфигурации VPS**, и вручную пройдите капчу, если она появилась. Дождитесь открытия редактора. Входить в свой Яндекс-аккаунт для публичного документа с редактированием не требуется. Если документ требует входа, сначала проверьте его общий доступ.

Для Firefox на другой ОС можно использовать тот же SSH-прокси: ручная настройка, SOCKS v5, `127.0.0.1:1081`, DNS через SOCKS. После завершения верните прежние настройки прокси.

## 4. Скопируйте Cookie успешного запроса документа

1. В отдельном окне Edge нажмите `F12` и откройте **Network / Сеть**.
2. Перезагрузите уже открывшийся документ с `Ctrl+Shift+R`.
3. Выберите запрос `https://docs.yandex.ru/edit/d/…` с типом **document** и статусом **200**, после которого виден редактор документа.
4. Откройте **Headers / Заголовки → Request Headers / Заголовки запроса**.
5. У строки **Cookie** скопируйте её **значение целиком**: `имя=значение; имя=значение; …`. Обычно доступна команда контекстного меню **Copy value / Копировать значение**.

Нужен Cookie запроса, отправленного **после** прохождения капчи. `Set-Cookie` из ответа, экспорт HAR, вся команда cURL и `document.cookie` не подходят для этого импортера. Последний способ, в частности, не возвращает HttpOnly cookies.

**Cookies вводятся только на своём VPS. Не отправляйте их в чат, Issue, комментарии или скриншоты.** Используйте отдельное окно без входа в личный аккаунт.

## 5. Импортируйте cookies на VPS

Вернитесь в обычную SSH-консоль сервера от `root` и вставьте весь блок:

```bash
bash <<'SH'
set -e
of_cookie_import=$(mktemp)
trap 'rm -f -- "$of_cookie_import"' EXIT
curl --proto '=https' --proto-redir '=https' \
  -fsSL --connect-timeout 15 --max-time 60 \
  https://raw.githubusercontent.com/Rublev13/OpenFlux_Instant_Installer_by_Ilya_Rublev/main/openflux-import-cookies.py \
  -o "$of_cookie_import"
python3 "$of_cookie_import"
SH
```

Когда появится **`Cookie:`**, вставьте скопированное значение и нажмите Enter. Символы на экране не отображаются; это нормально. Не вставляйте cookies в командную строку оболочки до появления этого приглашения.

Утилита проверит принадлежность установки, конфигурацию, права каталогов и параметры службы; остановит её на время записи; создаст резервную копию `/etc/openflux/cookies-before-import.json`; обновит cookies **только для текущего документа** и запустит службу. Остальные записи хранилища сохраняются. Файл cookies получит права `0600` и владельца службы; резервная копия — `0600`, только для root. Каждая новая операция заменяет предыдущую резервную копию. При ошибке записи служба может остаться остановленной, а старое хранилище остаётся доступно для восстановления.

Проверка в течение 20 секунд обнаруживает перезапуски, но не заменяет проверку интернета. Если процесс стабилен, подключите **одно** устройство и откройте сайт проверки IP. Адрес выхода должен соответствовать VPS. На телефоне должны совпадать документ, транспорт, ключ, кодек и Session. Режим сервера `ios` — это `legacy` без Session, в том числе при подключении совместимого Android-клиента.

После проверки закройте отдельное окно Edge и нажмите `Ctrl+C` в PowerShell, где запущен `ssh -N -D`. Этот SSH-прокси нужен только для получения cookies, а не для дальнейшей работы телефона.

## Если ошибка остаётся

Cookies могут истечь, а Яндекс — потребовать новую проверку. Возможны различия адресов IPv4/IPv6 и поведения браузера и транспорта. Поэтому успешное прохождение браузером капчи не гарантирует, что сервер примет эти cookies. Повторите [безопасную диагностику из README](README.md#подключено-и-пингуется-но-сайты-не-открываются); при сохранении ошибки остановите цикл командой `systemctl stop openflux.service`.

Для возврата предыдущего хранилища, только если резервная копия уже создана:

```bash
test -f /etc/openflux/cookies-before-import.json && \
systemctl stop openflux.service && \
install -m 600 -o openflux-rublev -g openflux-rublev \
  /etc/openflux/cookies-before-import.json /var/lib/openflux/cookies.json && \
systemctl start openflux.service
```

Утилита не исправляет несовпадение шифрования, ошибки VPN-режима клиента или проблемы WebSocket старого редактора. Для старых документов с уже успешной авторизацией нужна отдельная проверка обмена данными.

## Основания и пределы проверки

- [CookieStore OpenFlux 0.0.5, формат не изменился в v0.1.0](https://github.com/p1neappleXpress/OpenFlux/blob/ea52949d45c0284c532cb8295abadced58b3a389/transport/cookiestore.go) хранит объект `ссылка документа → имя cookie → значение`; [main.go](https://github.com/p1neappleXpress/OpenFlux/blob/ea52949d45c0284c532cb8295abadced58b3a389/main.go) загружает его перед запуском транспорта.
- [Issue #106](https://github.com/p1neappleXpress/OpenFlux/issues/106) содержит пользовательский отчёт о переносе cookies браузера на сервер. Это не гарантия работы для каждого документа и IP.
- [OpenSSH: `-D`](https://man.openbsd.org/ssh) — локальный SOCKS-прокси через SSH; [Edge: параметры прокси](https://learn.microsoft.com/en-us/deployedge/edge-learnmore-cmdline-options-proxy-settings) и [заголовки запросов](https://learn.microsoft.com/en-us/microsoft-edge/devtools/network/reference).

Автоматические тесты проверяют импорт для обоих редакторов, сохранение ключа и других документов, приватные права файлов, отказ при повреждённом хранилище, символьных ссылках и изменённых настройках службы. Проверены сохранность старого файла при ошибке записи и обнаружение перезапусков. Реальная капча Яндекса, работа Edge на пользовательском компьютере и сквозное соединение телефона с VPS не входят в эти тесты.
